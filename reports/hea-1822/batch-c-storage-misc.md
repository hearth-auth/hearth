## Defect List

- **[CRITERION F]** encryption.rs:463 — `unwrap_dek_with_wrong_kek_fails` — security-relevant AEAD rejection asserted only with bare `result.is_err()`; does not pin `StorageError::Crypto`. A failure for an unrelated reason (e.g. the "failed to create AEAD key" length branch, not an auth-tag failure) would pass vacuously. **P3**
- **[CRITERION F]** encryption.rs:481 — `unwrap_dek_with_wrong_kek_id_fails` — AAD-mismatch rejection uses bare `is_err()`; not pinned to the auth-tag failure variant. **P3**
- **[CRITERION F]** encryption.rs:509 — `decrypt_section_with_wrong_aad_fails` — bare `is_err()` on a security-critical AEAD negative; variant not pinned. **P3**
- **[CRITERION F]** encryption.rs:523 — `decrypt_section_with_wrong_dek_fails` — bare `is_err()`; wrong-key rejection not pinned to `StorageError::Crypto`. **P3**
- **[CRITERION F]** encryption.rs:537 — `decrypt_section_with_wrong_nonce_fails` — bare `is_err()`; nonce-mismatch rejection not pinned. **P3**
- **[CRITERION F]** encryption.rs:581 — `decrypt_kek_with_wrong_host_key_fails` — bare `is_err()`; KEK-unwrap wrong-host-key rejection not pinned. **P3**
- **[CRITERION F]** encryption.rs:594 — `decrypt_kek_with_wrong_kek_id_fails` — bare `is_err()`; not pinned to variant. **P3**
- **[CRITERION C]** breach_corpus.rs:285 / :297 — `is_pwned_finds_entry_at_beginning_of_corpus` / `is_pwned_finds_entry_at_end_of_corpus` — named for the public `is_pwned` API but assert the internal `binary_search` helper instead. Drift is documented in-body (constructing a password whose SHA-1 equals a fixed hash is infeasible), so justified, but the name overstates coverage of `is_pwned`. **P3**

### Coverage gap (not a defective test)
- **[CRITERION 4]** migrations.rs — `apply_migrations` has two `Err(DeserializationFailed)` branches (chain gap at :57, incomplete-reach at :65) that no test exercises. The module doc claims failure-on-gap behavior; it is unverified. Recommend a negative test (e.g. `apply_migrations(c, 0, 5)` → incomplete). **P3**

## Notes on strengths
- **encryption.rs** exercises real `ring` AES-256-GCM (no mocks); tamper proptest (`proptest_tampered_ciphertext_fails`) flips the GCM tag and asserts failure; wrong-key/tamper covered. The only weakness is variant-pinning, not missing negatives.
- **key_registry.rs** is the gold standard for this batch: every corruption/rotation/HMAC/production-mode negative pins the exact error variant and asserts operator-facing detail (`affected_realms`, reason substrings). `production_mode_refuses_autogenerated_host_key` conditional-skips only when `HEARTH_MASTER_KEY` is preset — legitimate, documented.
- No stale `#[ignore]`, commented-out asserts, `assert!(true)`, or `#[cfg(test)]`-gated production paths found in any file (Categories D, H clean).
