# Getting Started with Hearth

**Goal:** First authenticated request in your app. **Time:** ~5 minutes.

**Prerequisites:** `docker` and a package manager for your stack (`npm` / Go toolchain / `pip`). For the setup steps you also need `curl` and `jq`.

:::tip[SDK reference]
Step 3 adds browser login with the TypeScript SDK; step 4 checks permissions from TypeScript, Go, and Python backends. For deeper coverage — RBAC hooks, middleware patterns, and the Admin API — see the [SDK overview](/docs/sdks/overview).
:::

---

## 1. Run Hearth

```bash
docker run --rm -p 8420:8420 ghcr.io/hearth-auth/hearth:latest serve --dev --bind 0.0.0.0
```

`--dev` uses in-memory storage, enables the bootstrap endpoint, and starts the built-in **mailcatcher** (captured email at `http://127.0.0.1:8420/dev/mail`). **Data does not persist across restarts.**

Confirm it is up:

```bash
curl -fsS http://127.0.0.1:8420/health
# → {"status":"ok"}
```

:::tip[From source]
`make dev` or `cargo run -- serve --dev` — same flags, no Docker required. Rust toolchain must be installed.
:::

:::tip[Production deployment]
For Docker Compose, systemd, or Helm, see [`deploy/README.md`](../../deploy/README.md).
:::

## 2. Bootstrap a realm and register your app

Create a dev realm with an admin token, then register a public OAuth client for your app. Both are one-time **setup** — not application code.

```bash
# Create the dev realm + an admin token
BOOTSTRAP=$(curl -fsS -X POST http://127.0.0.1:8420/admin/bootstrap)
REALM_ID=$(echo "$BOOTSTRAP" | jq -r .realm_id)
ADMIN_TOKEN=$(echo "$BOOTSTRAP" | jq -r .access_token)

# Register a public client (no secret — PKCE secures it)
CLIENT_ID=$(curl -fsS -X POST http://127.0.0.1:8420/clients \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "X-Realm-ID: $REALM_ID" \
  -H "Content-Type: application/json" \
  -d '{"client_name":"quickstart","redirect_uris":["http://localhost:3000/callback"]}' \
  | jq -r .client_id)

echo "REALM_ID:  $REALM_ID"
echo "CLIENT_ID: $CLIENT_ID"
```

Your app (step 3) needs three values: the **realm slug** — `dev-realm` in `--dev` mode — the **`CLIENT_ID`** printed above, and the server URL `http://localhost:8420`.

:::warning[Dev-only endpoint]
`/admin/bootstrap` returns `404 Not Found` outside `--dev` mode. In production, create realms and register clients via `hearth.yaml` or the Admin API — never bootstrap.
:::

## 3. Add login to your app

Logging a user in is the OAuth 2.0 authorization-code + PKCE flow: send the user to Hearth to authenticate, then exchange the returned `code` for tokens on your callback route. The TypeScript SDK uses the `createHearthAuth` browser facade; every server SDK uses `beginLogin` to build the redirect URL and `completeLogin` to exchange the code. Every tab uses the realm slug `dev-realm`, the `CLIENT_ID` from step 2, redirect URI `http://localhost:3000/callback`, and server `http://localhost:8420`.

<Tabs groupId="lang">
<TabItem value="ts" label="TypeScript" default>

```bash
npm install @hearth-auth/sdk
```

**Login page** — redirect the browser to Hearth:

```ts
import { HearthApiClient, createHearthAuth } from '@hearth-auth/sdk';

const client = new HearthApiClient({
  baseUrl: 'http://localhost:8420/realms/dev-realm',
  realmId: '<realm-id>',
});

// createHearthAuth handles PKCE, stores tokens, and auto-refreshes.
const auth = createHearthAuth(client, {
  clientId:    '<client-id>',
  redirectUri: 'http://localhost:3000/callback',
  hearthUrl:   'http://localhost:8420',
  realmSlug:   'dev-realm',
});

await auth.startLogin();
```

**Callback page** — exchange the code and store tokens:

```ts
const p = new URLSearchParams(window.location.search);
await auth.handleCallback(p.get('code')!, p.get('state')!);
// Tokens are now stored and auto-refreshed.
```

<TabItem value="curl" label="curl">

```bash
# 1. Generate an S256 PKCE pair, then open the login URL in a browser.
VERIFIER=$(openssl rand -hex 32)
CHALLENGE=$(printf '%s' "$VERIFIER" | openssl dgst -sha256 -binary | openssl base64 -A | tr '+/' '-_' | tr -d '=')
echo "http://localhost:8420/realms/dev-realm/authorize?response_type=code&client_id=$CLIENT_ID&redirect_uri=http://localhost:3000/callback&scope=openid&state=xyz&code_challenge=$CHALLENGE&code_challenge_method=S256"

# 2. After logging in, exchange the ?code= you were redirected with.
curl -fsS -X POST http://localhost:8420/token -H "X-Realm-ID: $REALM_ID" \
  --data-urlencode grant_type=authorization_code \
  --data-urlencode code=$CODE \
  --data-urlencode client_id=$CLIENT_ID \
  --data-urlencode redirect_uri=http://localhost:3000/callback \
  --data-urlencode code_verifier=$VERIFIER | jq -r .access_token
```

The access token is signed with your realm's Ed25519 key, and its `permissions` are resolved at issue time — checking them needs no network call (step 4).

:::tip[TypeScript vs server SDKs]
The TypeScript SDK ships `createHearthAuth` — a **stateful browser facade** that stores tokens in `sessionStorage` and handles silent refresh. Every server SDK (Node, Go, Python, PHP, Rust, Kotlin) ships **stateless** `beginLogin`/`completeLogin` helpers: `beginLogin` returns the values you persist in your session, `completeLogin` exchanges the code. See the [`full-stack-demo`](https://github.com/hearth-auth/hearth/tree/main/examples/full-stack-demo) for a complete Vite + React + Node example.
:::

:::note[Node server handling the callback?]
If your Node.js server owns the OAuth callback route (Next.js API routes, Express, Fastify), use `client.beginLogin()` / `client.completeLogin()` — see the [Node SDK](/docs/sdks/node). For browser-hosted login (React SPA, Next.js client components), use the TypeScript SDK tab above.
:::

## 4. Protect a route in your app

Fetch Hearth's public signing keys from the JWKS endpoint and verify incoming Bearer tokens cryptographically. The Hearth SDKs provide middleware for the most common frameworks.

The following examples guard a route and check that the caller has the `hearth.admin` permission.

<Tabs groupId="lang">
<TabItem value="ts" label="TypeScript" default>

```bash
npm install @hearth-auth/sdk jose
```

```ts
import { requirePermission } from '@hearth-auth/sdk';
import express from 'express';

const app = express();

app.get('/admin/data', requirePermission('hearth.admin', {
  issuerUrl: process.env.HEARTH_URL!,       // e.g. https://auth.example.com
  realmId:   process.env.HEARTH_REALM_ID!,
}), (req, res) => {
  res.json({ message: 'authorized', user: req.user });
});
```

</TabItem>
<TabItem value="node" label="Node">

```bash
npm install @hearth-auth/node
```

```ts
import { HearthClient } from '@hearth-auth/node';

const client = new HearthClient({
  issuer_url: process.env.HEARTH_URL!,       // e.g. https://auth.example.com
  realm_id:   process.env.HEARTH_REALM_ID!,
});

// In your Express / Fastify handler — `bearer` is the Authorization token:
const token = await client.verifyToken(bearer);   // verifies the Ed25519 signature via cached JWKS
if (!token.hasPermission('hearth.admin')) {
  res.status(403).end();
}
```

</TabItem>
<TabItem value="go" label="Go">

```go
import (
    "net/http"
    "strings"
    "github.com/hearth-auth/hearth/sdks/go/hearth"
)

client := hearth.NewClient(hearthURL, realmID)

func adminOnly(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        token := strings.TrimPrefix(r.Header.Get("Authorization"), "Bearer ")
        if !client.HasPermission(token, "hearth.admin") {
            http.Error(w, "Forbidden", http.StatusForbidden)
            return
        }
        next.ServeHTTP(w, r)
    })
}
```

</TabItem>
<TabItem value="python" label="Python">

```python
from hearth import HearthClient

def require_permission(permission: str):
    """FastAPI / Flask dependency — checks permission from the JWT claim set."""
    def check(authorization: str):
        token = authorization.removeprefix("Bearer ")
        if not HearthClient.has_permission(token, permission):
            raise HTTPException(status_code=403, detail="Forbidden")
        return token
    return check
```

</TabItem>
<TabItem value="php" label="PHP">

```php
use Hearth\HearthClient;

$hearth = new HearthClient(issuerUrl: $hearthUrl);

// In your PSR-15 / Laravel middleware:
$token  = str_replace('Bearer ', '', $_SERVER['HTTP_AUTHORIZATION'] ?? '');
$claims = $hearth->verifyToken($token);   // verifies the Ed25519 signature via cached JWKS

if (!$claims->hasPermission('hearth.admin')) {
    http_response_code(403);
    exit;
}
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use hearth_sdk::HearthClient;

// `token: &str` is the Bearer value from the Authorization header.
if !HearthClient::has_permission(token, "hearth.admin")? {
    // reject with 403 Forbidden
}
```

</TabItem>
</Tabs>

The local RBAC checks — `requirePermission` (TypeScript), `HasPermission` (Go), `has_permission` (Python, Rust) — read the `permissions` array embedded in the token at issue time by Hearth's RBAC engine, with no network call. The `verifyToken()` calls (Node, PHP) additionally validate the token's Ed25519 signature against the realm's cached JWKS before the check.

Prefer no SDK? Verify tokens directly against the realm's JWKS endpoint — see [Token verification without an SDK](/docs/sdks/overview#token-verification-without-an-sdk).

For browser SPA and BFF token-storage patterns, see [Browser / SPA token handling](browser-spa-tokens.md).
